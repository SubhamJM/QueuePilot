# OOP Concept Mapping

Where each concept required by CS1207 appears in real code (not in classes created only to show a concept).

| Concept | Where | Why it is there |
|---|---|---|
| **Encapsulation** | `coordinator/job/JobEntity` (`start`, `succeed`, `retryLater`, `fail`, `cancel`, `skip`), `attempt/AttemptEntity` (`accepts`, `renewLease`, `finish`), `worker/WorkerEntity` (`canRun`, `takeCommand`) | State can only change through methods that enforce the lifecycle; there are no public setters for `state` |
| **Abstraction** | `task-api/TaskExecutor`, `TaskContext`; `core/scheduling/SchedulingPolicy`; `coordinator/artifact/ArtifactStorage`; `worker/CoordinatorApi` | Callers depend on what is done, not how: the scheduler never sees task code, the worker logic never sees HTTP |
| **Inheritance** | `coordinator/error/ApiException` → `Errors.NotFoundException`, `ConflictException` → `StaleAttemptException`, `ValidationException`; `task-api/TaskFailure extends Exception`; `test/MutableClock extends Clock` | Each subclass supplies its HTTP status and code; a stale attempt *is a* conflict |
| **Polymorphism** | `GlobalExceptionHandler.handleApi` calls `e.status()` on any `ApiException`; `SchedulerService` calls `policy.order(...)` on whichever policy is active; `AttemptRunner` calls `executor.execute(...)` on any plugin | Behaviour chosen at runtime by the object, not by `if/else` on a type field |
| **Composition** | `SchedulerService` has a `QueueRotation`, a settings service (which holds the active `SchedulingPolicy`) and an `AttemptService`; `WorkerRuntime` has an `ActiveAttempts`, a `TaskExecutorRegistry`, a `Semaphore`, thread pools; `JobEntity` owns its prerequisite set | Behaviour assembled from small parts instead of deep hierarchies |
| **Collections** | `TreeMap` in `QueueRotation` and `TaskExecutorRegistry`; `LinkedHashMap<String, Set<String>>` adjacency in `DependencyGraph`; `PriorityQueue<Long>` of worker free times in `Simulator`; `EnumMap`/`EnumSet` in `JobStateMachine`; `ConcurrentHashMap` in `ActiveAttempts` | Each chosen for ordering, lookup or thread-safety needs |
| **Exception handling** | Validation errors collected into `ValidationException`; `TaskFailure` retryable vs permanent; `AttemptRunner` maps every exception type to an outcome; `RecoveryMonitor` isolates per-item failures; `HttpCoordinatorClient` turns HTTP errors into `CoordinatorException` | Failures are expected events with defined consequences |
| **Multithreading** | Worker: claim-loop thread, fixed execution pool, scheduled heartbeat and timeout timers, virtual-thread output reader in `JavaScriptTask`; Coordinator: `@Scheduled` recovery monitor, concurrent HTTP requests | Real parallel execution of jobs |
| **Synchronization** | `Semaphore` slot limit in `WorkerRuntime`; `AtomicReference`/`AtomicBoolean` cancellation flags; `synchronized` `QueueRotation` and progress throttling; database optimistic locking (`@Version`) for claims | Prevents over-subscription, lost updates and double assignment |
| **File handling** | `LocalFileArtifactStorage` (streaming, size limit, SHA-256), `TextAnalysisTask`/`FileChecksumTask` (reading inputs, writing CSV), worker scratch directories, `ReportWriter` (CSV/JSON reports) | Inputs and outputs that do not fit in JSON |
| **Database connectivity** | Spring Data JPA repositories (`JobRepository` with JPQL queries and a conditional bulk update), Flyway SQL migration, `JdbcTemplate` health check | Persistence is the source of truth |
| **Design patterns** | Strategy (`SchedulingPolicy`), Registry (`TaskRegistryService`, `TaskExecutorRegistry`), Factory method (`PolicyType.create`), Template-free plugin discovery via `ServiceLoader` | Used where they remove `switch`es or decouple modules |
| **Interfaces with multiple implementations** | `SchedulingPolicy` (3), `TaskExecutor` (5 incl. example plugin), `CoordinatorApi` (HTTP + test fake), `TaskContext` (worker + test fakes) | An interface only where there is a real second implementation or plugin boundary |
| **Records / immutability** | `SchedulableJob`, `WorkerProtocol.*`, `ScheduleMetrics`, `Stats`, views/DTOs | Data carriers that cannot be modified after creation |
